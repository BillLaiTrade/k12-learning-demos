# 1.1 第三學習區塊：三孔板通光修正

日期：2026-10-29

## 核可範圍

使用者在討論後核可修正「依三片孔板實際能否讓直線光通過，判斷屏幕是否出現亮點」。保留三片板、拖曳／高度滑桿、重設及版面；本次不修改其餘學習區塊、故事架構或單元小冊。

## 問題與修正

舊程式使用三片板的最大高度偏移量估算亮度，並把20%以下視為完全不通光；各片指示燈也只看自己的偏移，未考慮上游已擋光。`before-zigzag.png` 保存前次唯讀檢視時重現的 +40／−40／+40 案例：不存在共同直線通路仍顯示有部分光。

新增無Three.js依賴的 `aperture-optics.mjs`，沿用出光點 x=-4、光軸 y=1.28、屏幕 x=4.265 及半徑0.15的既有光斑。小光源發出的窄角光束，必須依序通過每片高0.36、寬0.42、厚0.12孔板的前後孔口。以直線交點將孔口限制換算至屏幕，逐片取共同通路，並以圓形光束剩餘面積的解析積分求通光比例；前後位置及板厚均會影響結果。孔口尺寸與渲染幾何共用常數。

亮點／外暈依剩餘光量顯示或隱藏；指示燈依實際前後順序顯示穿過該片板後的光。前方完全擋光時，下游不再亮通光燈號，title及可及名稱會說明上游擋光。完整通光文字亦不再把孔中心精確共線視為必要條件，保留有限孔口容許些微偏移的情況。

模型假設光束在既有光斑內均勻分布；它檢查的是這組窄角光束的幾何通路，未重建整個燈具的發光分布、波動衍射、散射或精確屏幕照度。亮點沿用亮度／尺寸表示相對通光量的教學示意，未改為精確截面影像。
